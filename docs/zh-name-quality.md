# 中文名质量：小黑盒「主标题」不是「中文标题」

> 快照 2026-10-31 15:15 · name_zh 共 7,530 条 · 标记 831 条（11.0%）

## 前提

小黑盒的每个游戏有两个标题字段：**主标题**和**原英文标题**。我们抓的是主标题，早期默认「主标题一定
是中文」，实测并非如此——一部分小众游戏没做汉化，主标题本身就是日文或英文，于是被「含汉字即算中文名」
的判定规则放进了 `games.name_zh`。

这类游戏数量少、受众窄，**当前决定是照旧存储，不做清洗**，等日后有更好的取名方案再统一处理。

## 字段构成实测（2026-10-31 15:21，games 共 52,202 行）

「标准」这个判定**只对 `name_zh` 定义过**，`name_en` 没有标准可言（它只作副标题和搜索用）。

`name_zh` —— UI 主标题用的字段，有值 7,545 条：

| 文字构成 | 条数 | 占比 | 算不算标准 |
|---|---|---|---|
| 纯中文（可含 3D/VR/GT 等通用缩写） | 6,706 | 88.9% | ✅ 标准 |
| 中英混合 | 811 | 10.7% | ❌ 需人工判断 |
| 汉字 + 假名（日文） | 27 | 0.4% | ❌ 不标准 |
| 韩文 | 1 | 0.0% | ❌ 不标准 |
| 空 | 44,657 | — | 未采集到 |

`name_en` —— 原始英文名字段，52,202 行全覆盖（0 空），但**不全是拉丁字母**：

| 文字构成 | 条数 |
|---|---|
| 纯拉丁字母 | 51,493（98.6%） |
| 中英混合 | 281 |
| 纯中文 | 277 |
| 汉字 + 假名 / 纯假名（日文） | 59 + 13 |
| 仅数字或符号 | 42 |
| 西里尔（俄文等） | 26 |
| 韩文 | 11 |

两点注意：

1. **纯拉丁 ≠ 英文**。PCGamingWiki 给的是「原名」，德/法/西语的标题同样是拉丁字母
   （如 `Crazy maze ~疯狂迷宫 ~ 狂った迷路 ~ Laberinto loco ~ Labyrinthe fou ~ Verrücktes Labyrinth`）。
2. 那 277 条纯中文的 `name_en` 值得单独看一眼——大概率是这些游戏本来就没有英文名。

## 不要误伤的

拉丁字母本来就是名字的一部分，这类必须保留：

- `3D迷你高尔夫`、`5D国际象棋的多维时空旅行`（2D/3D/数字前缀）
- `9-nine-九次九日九重色`（拉丁粘在中文前，无空格）
- `骇客时空GU 最终编码`、`魂斗罗：RC联盟`（缩写夹在中文里）

脚本用「前缀是 2D/3D/数字后接汉字」和「拉丁占比」两个条件把它们排除了。

## 英文名来源与切换方案（2026-10-31 定）

戢翎定的路子：**wiki 的名字先当临时兜底，采集完成后全面改用我们自己采的数据**，让中文名和英文名都符合规范。

前置事实（实测，不是推测）：

- 小黑盒详情接口的 `result` 里有 **`name_en`** 字段，就是「原英文标题」。
  验证：appid 730 → `name='CS2'`、`name_en='Counter-Strike 2'`。
- 已给 `name_sources` 加列 `name_en`，采集器 `xiaoheihe_zh.py` 已改为同时写主标题和英文标题
  （老库缺列时自动 ALTER，补列失败则退回只写主标题）。

**切换优先级（待采集完成后由 rebuild 执行）**

| 字段 | 优先级 |
|---|---|
| `name_zh` | 小黑盒主标题（含汉字）> Steam 官方 `ok` > 留空（不拿 wiki 填） |
| `name_en` | **Steam 官方 `name_en`** > 小黑盒 `name_en` > PCGW 原始 title |

英文名官方最高（2026-10-30 戢翎定的规则）：Steam 官方给的是真正的英文标题，小黑盒的 `name_en`
只是它自己的英文字段，可能残缺或仍是原名，所以排第二，仅作兜底。

**Steam 官方数据的现状**（这是关键缺口）

| 项 | 数值 |
|---|---|
| 已采 `steam_names` | 3,947 条 |
| 占有 appid 游戏的 | **8.0%**（3,947 / 49,268） |
| 其中 `name_en` 非空 | 3,805 条（97%） |

当时采这个表是为了**补中文名**做的抽样，不是全量，所以英文名这块等于没铺开。
要全量得再跑一遍：每个 appid 先请求 `l=schinese`，有中文再补一次 `l=english`
→ 约 6.9 万次请求，按 appdetails 限速 40 次/分钟算 **约 29 小时**。


**覆盖率现实**（别指望 100%）

- 能采的游戏：有 `steam_appid` 的 49,315 / 52,202（94.5%），剩 2,887 条没有 appid，小黑盒无从下手。
- 接口有响应率约 75%（已采 21,400 里 16,113 有结果）→ 英文名最终覆盖约 **7 万→3.7 万条，约 71%**。
- 中文名命中率约 35%（`named 7,520 / 已采 21,400`）→ 最终约 **1.7 万条，约 33%**。

所以现实目标是「**优先用自己采的，缺的由 wiki 兜底**」，做不到「把 wiki 完全踢掉」。

**已有数据的缺口**：改脚本之前采的 21,400 条没有 `name_en`（那 21k 次请求当时只取了主标题）。
要补齐得多发约 2.1 万次请求（≈ 3 轮 / 1 天），或者接受这批只有中文、英文继续用 wiki。

## 日后重采的思路（未实施）

1. 拉小黑盒详情时同时取「原英文标题」字段，用它判断主标题是否只是英文原名的拷贝；
2. 主标题含假名 → 判非中文，不写 `name_zh`；
3. 主标题是 `中文 / English` 结构 → 只取中文段；
4. 剩下的英文名走 Steam 官方 `l=schinese` 补一次，仍没有就留空。

判定规则要落在**落库前**，不能事后批量改主表——2026-10-30 那次 `name_en` 被污染 224 条就是教训。
